# 数据存储方式说明

## 1. 总体架构

本项目数据存储采用 **CSV文件 + MySQL关系数据库** 双层架构：

| 层级 | 用途 | 格式 | 位置 |
|------|------|------|------|
| 原始数据层 | 爬虫采集的原始数据留存 | 197 个独立 CSV 文件 | `D:\Desktop\作业\数据可视化\爬虫数据（部分原始数据）\` |
| 标准数据层 | 清洗后的统一数据集 | 单文件 CSV (UTF-8 BOM) | `all_cities_all_years.csv` |
| 数据库层 | 聚合查询与 API 服务 | MySQL 8.0+ | `air_quality` 数据库 |

## 4. MySQL 数据库存储

### 4.1 数据库信息

| 属性 | 说明 |
|------|------|
| 数据库名 | `air_quality` |
| 字符集 | `utf8mb4`（支持中文） |
| 排序规则 | `utf8mb4_unicode_ci` |
| 总表数 | 22 张（2 张基础表 + 20 张聚合表） |

### 4.2 基础表结构

#### records 表（主数据表）

```sql
CREATE TABLE records (
    id          BIGINT AUTO_INCREMENT PRIMARY KEY,
    city        VARCHAR(64)  NOT NULL,
    date        DATE         NOT NULL,
    quality_level VARCHAR(16),
    aqi         FLOAT,
    aqi_rank    FLOAT,
    pm25        FLOAT,
    pm10        FLOAT,
    so2         FLOAT,
    no2         FLOAT,
    co          FLOAT,
    o3          FLOAT,
    year        SMALLINT     NOT NULL,
    month       TINYINT      NOT NULL,
    season      VARCHAR(4),
    level_code  TINYINT,
    INDEX idx_city_date (city, date),
    INDEX idx_year_month (year, month),
    INDEX idx_city_year (city, year),
    INDEX idx_date (date)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

#### cities 表（城市坐标表）

```sql
CREATE TABLE cities (
    name    VARCHAR(64)  PRIMARY KEY,
    region  VARCHAR(16),      -- 所属区域（华北/东北/华东/华中/华南/西南/西北）
    lng     DOUBLE,           -- 经度
    lat     DOUBLE            -- 纬度
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

### 4.4 索引策略

- **records 表**：`city + date` 联合索引（最常用查询路径）、`year + month` 索引（时间范围查询）、`city + year` 索引（年度城市分析）
- **聚合表**：全部使用复合主键覆盖查询条件，避免回表

### 4.5 数据流

```
原始爬虫数据（197 CSV）  →  清洗脚本（12步）  →  清洗后标准CSV（15列）
                                                          │
                                                    init_db.py
                                                          │
                                                          ▼
                                              MySQL (air_quality)
                                              ├── records (584K行)
                                              ├── cities (328行)
                                              └── 20张聚合表（pandas预计算 → 批量写入）
```

### 4.6 后端查询策略

Flask API 通过 `data_loader.py` 访问数据，采用 **MySQL 优先、CSV 回退** 策略：

1. 启动时尝试连接 MySQL，若成功则所有 API 查询走聚合表（毫秒级响应）
2. 若 MySQL 不可用，自动回退到 CSV + pandas 内存计算模式
3. 聚合表由 `init_db.py` 一次性预计算写入，运行时不再做复杂 OLAP
